### CRITICAL REQUIREMENT: Advanced Compress Image Tool

The Compress Image tool must combine image resizing and image compression in one complete interface.

#### A. Image upload

- Support file selection and drag-and-drop.
- Display the original image preview.
- Display the original width and height in pixels.
- Display the actual original file size in KB or MB.
- Validate image types and reject invalid or unsupported files.
- Handle large images and processing errors gracefully.

#### B. Exact pixel resizing

Allow users to enter exact output dimensions, including examples such as:

- 500 × 500 pixels
- 1280 × 720 pixels
- 1920 × 1080 pixels

Include:

- Numeric width and height inputs.
- A "Maintain Aspect Ratio" checkbox, enabled by default.
- Automatic calculation of the corresponding dimension when one value changes.
- Independent width and height editing when aspect-ratio maintenance is disabled.
- Percentage resizing presets: 25%, 50%, 75%, and 100%.
- A Reset Dimensions button.
- Validation for zero, negative, invalid, and excessively large dimensions.

When aspect ratio is enabled, preserve the original image proportions and explain that the resulting dimensions may differ from the requested dimensions if both cannot be satisfied simultaneously.

When aspect ratio is disabled, allow the user to set exact dimensions even if the image becomes stretched.

#### C. Compression by target file size

Allow users to request a target output file size in KB or MB.

Provide presets:

- 50 KB
- 100 KB
- 200 KB
- 500 KB
- 1 MB

Also provide:

- A compression quality slider from 10% to 100%.
- Appropriate output format settings.
- Actual output file-size measurement.
- An optional target-size optimization process.

When the selected format supports adjustable lossy quality, attempt to reach the target size by adjusting quality, and optionally reduce dimensions only if the user has enabled that option.

Never silently reduce dimensions when the user requested compression only.

If the target size cannot be achieved, show the actual size and explain why. Do not claim that the target was reached unless the resulting file actually satisfies it.

Explain that exact file sizes are not always achievable.

#### D. Output formats and transparency

Provide supported output options:

- JPEG
- PNG
- WEBP

Check actual browser support before processing.

Requirements:

- Preserve transparency when the output format supports it.
- Warn users when converting a transparent image to JPEG because transparency may be replaced with a solid background.
- Use correct MIME types and file extensions.
- Do not silently substitute another format.
- If a fallback is necessary, inform the user and update the displayed format and filename.

#### E. Actual image processing

Use the Canvas API, createImageBitmap, or a reliable compatible library.

Implement two separate actions:

**Resize Only**
- Change the image dimensions.
- Avoid intentionally lowering image quality beyond the selected format's encoding requirements.
- Clearly explain that re-encoding may still change file size or quality.

**Compress and Resize**
- Apply the chosen dimensions, output format, and compression settings.
- Optimize quality toward the requested target size where supported.

For both actions:

- Process the real image data.
- Generate a real output Blob or File.
- Display the processed image preview.
- Display actual output dimensions and file size.
- Provide a working Download Image button.
- Use an appropriate filename, such as `image_resized_compressed.webp`.
- Show processing status and meaningful error messages.
- Clean up temporary object URLs when no longer needed.

Calculate the actual file-size reduction using:

Reduction (%) = ((Original file size - Output file size) / Original file size) × 100

If the output file is larger, display the actual result rather than falsely reporting a reduction.

#### F. Before-and-after comparison

Display:

- Original image and processed image.
- Original and output dimensions.
- Original and output file sizes.
- Actual percentage reduction.
- Output format.
- A working download button.

Use a side-by-side comparison on desktop and a stacked layout on mobile.

#### G. Compress Image interface

Arrange the page into clear sections:

1. Upload Image
2. Original Image Information
3. Resize Dimensions
4. Compression Settings
5. Output Format
6. Processing Controls
7. Before-and-After Comparison
8. Download Result

Use clear labels, helpful instructions, validation messages, and accessible controls.
